# 发布前问题分级：P0 / P1 / P2

适用于新建、转换、升级的基础检查和 BASIC 审核。Basic 复用已有检查，不为定级再插入第二次审核。按实际影响定级，不按文件类型机械判断。

| 等级 | 标准与示例 | 处理 |
| --- | --- | --- |
| P0 | 编译不通过、语法错误、config 存在不合规字段／类型／必填项缺失、入口或必需依赖／资源缺失、积木与生成器映射断裂、生成代码无法编译；已确认的核心行为与需求相反 | 阻止审核通过及发布，不停止后续审核；完成本次范围内可执行检查后统一报告，开发流程修复后复查受影响项 |
| P1 | 命名不规范、图片样式／清晰度、积木颜色、非核心本地化缺失、菜单分组不合理、帮助说明不足 | 提醒为主，默认不阻止发布，不逐项索取确认 |
| P2 | 展示署名与仓库所有人不一致、积木文字有歧义但实现明确、排版、多余空格、代码风格、注释完善、非必要重构 | 可以不改，不自动修改或为了统一风格重构第三方源码 |

## 影响边界

- 正常 fork 保留原作者而仓库属于当前用户，不是缺陷；只有会误导使用者的展示差异才列建议。实际推送目标与授权目标不一致必须停止，与 P2 无关。
- 文字表达不清而实现符合需求可列 P2；“前进”实际生成后退代码，或参数顺序错误导致核心行为错误，应列 P0。
- 新建项目外层目录的 `ext2-` 前缀是[创建前路径约束](project-naming.md)，不受 P1 命名建议豁免；已有仓库不强制改名。
- 图片样式属于 P1，必需图片引用不存在导致加载失败属于 P0；命名风格属于 P1，标识符冲突导致编译或加载失败属于 P0。
- 未执行构建、Mind+ 或硬件验证单列“未验证”，注明范围和原因，不标成缺陷或 PASS。可选检查用 NOT_RUN；已执行且发现源码编译错误才是 P0。依赖下载或环境失败不冒充代码编译失败。
- Python 依赖按 [review-basic.md](review-basic.md) 判断：标准库和目标环境内置库不要求额外声明；只有需额外安装的第三方库缺声明才提醒 P1。实际运行错误按证据判断。
- 契约要求的是“字段完整出现”，不是“字段必须有值”。`compatibilityId`、`sku`、`meta.runtimeVersion` 等没有证据时按 [config-schema.md](switch/config-schema.md) 写 `""` 是正确做法，不是缺陷，不列 P0／P1／P2——包括以“Empty compatibilityId”一类命名回报的“空字段”发现。P0 的“必填项缺失”只指必需字段不存在、类型不符、固定值不符或出现白名单外字段；字段已出现但值为空字符串不构成任何等级的问题。只有已确认需要兼容却留空、或以空值掩盖无法证明的身份（见 [conventions.md](switch/conventions.md)）才是需要处理的问题。
- Basic 的构建、积木显示／行为、恶意代码审查和 ZIP ≤ 5,000,000 字节是发布必需门槛；缺失验证或超限不发布，不能用 P1/P2 降级。凭据泄露、授权缺失、仓库归属／fork 前提、发布目标、版本提升要求、来源完整性和提交／远端哈希核验继续作为独立门槛，不允许降级绕过。

## 检查与交接

保留原始检查输出。检查器一次报告多类问题时，逐项分类，并记录文件位置、实际影响和证据；不能把原始 FAIL 改写成 PASS。仅含样式建议的汇总 FAIL 不自动升级为 P0，应从原始输出分别形成有依据的功能门槛检查和建议项。不确定影响时继续定位或注明未验证，不能把已确认的 P0 降为 P1。

`config_schema`、`extension_static_integrity`、`source_semantics` 等必需检查表示其声明范围内的功能门槛。把颜色、排版、文字歧义等单独记为建议项；不要让它们污染功能门槛的结果。必需检查 PASS 仍需证据。

使用 `mpa.py handoff` 的 `--priority <check_id>=P0|P1|P2`：

```text
--check block_color=FAIL --priority block_color=P1 --evidence block_color=<evidence-file>
--check trailing_spaces=FAIL --priority trailing_spaces=P2 --evidence trailing_spaces=<evidence-file>
--check syntax_error=FAIL --priority syntax_error=P0 --evidence syntax_error=<evidence-file>
```

每个例子是附加到实际 handoff 命令的参数片段，不是独立命令。P1/P2 自动设为 optional，保留 FAIL 表示问题仍存在；只含这些建议且所有必需门槛满足时，整体可 PASS。P0 必须 required，FAIL 时整体不能 PASS，也不能通过 `--optional` 绕过。显式验收和独立发布门槛不使用建议级别。原有不含 priority 的交接继续按 required/result 校验。

完成本次范围内所有可执行检查后，再向用户统一报告审核结论和是否可进入发布，列出全部 P0 必须修改、P1 提醒、P2 可选和未验证项；每个问题说明位置、实际影响和证据，每个未验证项说明原因。不得因首个或多个 P0 提前结束审核或要求先修复；无法执行的检查保留真实结果，继续其余独立检查。无 P0 且独立前提满足时按已有发布授权继续；不要因建议项反复要求重新构建或完整验收。
