# 新建扩展的 author

本规则仅用于 CREATE_FRESH 的作者选定，在冻结 `extension-spec.json` 前完成；转换、升级和 fork 保留有来源的原作者，不根据当前电脑或登录账号重新署名。

## 来源与规范化

1. 优先使用用户明确给出的作者名；否则使用已知的当前登录账号名、目标项目适用的 Git `user.name` 或当前电脑的用户账号名。读取可发现的本地信息，不为取名字要求登录或提供令牌。电脑用户账号不等于主机名；Git 作者配置也不证明远端仓库归属。
2. 新建 author 使用非空 ASCII 英文字母（`A-Z`、`a-z`）。先将全角字母转半角、拉丁字母重音转普通字母，再去除空格、数字和标点；中文名按可确定的拼音转写。例如 `Li Ming_01` → `LiMing`，`张三` → `ZhangSan`。保留合理大小写；不要把邮箱域名混入作者名。
3. 用户提供的名称不合规时先规范化，并在规格或结果中简要记录原名、最终值与来源。转写有歧义或去除无效字符后没有字母时，使用另一个有依据的账号候选；仍无有效名字时，只询问一个英文署名，不填无依据的默认作者。
4. 没有用户明确要求时，不采用 `DFRobot`、`MindPlus`（忽略大小写），即使模板、电脑账号或 Git 配置使用了这些名字。继续寻找个人署名候选；不得把模板作者当作新库作者。用户明确指定这两个名字时允许使用。

## 应用范围

将选定值一致写入新建规格 `identity.author` 和扩展 `config.author`。新建库的 `compatibility_id` 默认留空；仅确认旧库兼容需求时使用有来源的旧身份，不根据新作者或新 ID 派生；不要改写已有库的兼容身份、版权声明或 Git 配置。

这些是新建作者的输入约定，不是重新判定旧库 config 合法性的依据。读取用户／账号名称只用于署名，不替代发布阶段的身份、授权或 fork 核验。
