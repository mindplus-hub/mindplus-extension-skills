# Skill update at task entry

Before routing each new task, run `python <absolute path of this skill directory>/scripts/update_skill.py` from any working directory (always pass the absolute script path; the working directory does not matter and the script never renames the skill directory). Compare installed `VERSION` (see root `VERSION`) with stable releases at `https://gitee.com/mind-plus/mindplus-extension-skills/releases/`. Runtime files at root/one child directory select the WB ZIP; deeper runtime directories select the universal ZIP. Install only a newer matching Release package, retaining one compressed rollback ZIP outside skill discovery directories. Never run the updater from `.mindplus-skill-backups`, a staging directory, or a packaged preview. Use the active skill path reported by the client, not a directory found by broad search. Do not automatically delete historical backups or staging directories. If the user reports a known newer release, add `--refresh` to bypass the one-hour check cache. On success verify the returned `installation_root` is the active skill and `installed_version` matches that directory's `VERSION`; updating another copy is not success. On `UPDATED`, reload this directory's `SKILL.md` before continuing. On `SKIPPED`, briefly report the reason and continue with the installed version; never force overwrite local Git changes. Do not repeat the check within the same task or an active run. If the user explicitly requests offline use or a pinned version, skip the check.
