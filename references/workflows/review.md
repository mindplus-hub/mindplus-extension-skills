# Leaf: Basic review before publication

Load for `REVIEW_EXISTING`. Read [review-basic.md](../review-basic.md) for the eight required checks, safety-before-execution order, ZIP limit and source/artifact-bound evidence. Review preserves extension source. Authorized builds/checks may produce artifacts and evidence; correct source defects in development, then refresh affected checks.

This leaf follows CREATE/CONVERT/UPGRADE and precedes PUBLISH. An existing project may also enter it directly. Reuse valid producer evidence rather than repeating work. Missing build/display/behavior evidence is BLOCKED, not a successful static-only Basic. Report P1/P2 suggestions without requiring fixes; unresolved P0 or independent gates block. Apply the Python dependency rules in [review-basic.md](../review-basic.md); do not infer a missing dependency from an import alone. A required field that is present but left empty by contract (`compatibilityId`, `sku`, `meta.runtimeVersion`) is correct, not a defect: report no severity for it and do not raise findings such as "Empty compatibilityId". The `required_fields` gate checks presence, type and fixed values only.

P0 blocks approval and publication, not the remaining review. On either branch, record each finding and continue all reachable checks in the selected scope; do not hand off early or require fixes before completing the review. If a failed prerequisite or an unsafe execution prevents a check, record that check as `NOT_RUN` / `BLOCKED` with the specific reason and continue the independent checks. Finish with one report covering every scoped check, all P0/P1/P2 findings with locations, impact and evidence, and all unverified items with reasons.

After completing the scoped checks, run `scripts/check_basic_review.py` for full Basic, attach its passing report as `basic_review`, and hand off `REVIEWED_BASIC` with all eight required checks. A failed or incomplete report cannot advance to publication. Resume after obtaining the missing evidence; do not edit logs to manufacture PASS.

## Report-first branch

Take this branch for a review-only request asking what is wrong with the project: "列出具体问题", "不修改文件", "看有没有问题" and a bare "审核一下" all qualify. A repository URL or Gitee name identifies the source; it does not by itself request publication readiness.

Run the full eight-check Basic for an explicit complete Basic / publication-readiness request, a route with a producer or publication successor, or a project already staged for publication. Resolve genuinely conflicting requested outcomes before evidence work; do not ask merely because the project looks publishable.

On this branch, execute the four static checks (`config_schema`, `extension_static_integrity`, `source_semantics`, `malicious_code_review`) and classify P0/P1/P2. Reuse current build evidence if available; otherwise build only when requested or needed to resolve a specific finding within the authorized scope, not merely because an artifact is absent. Record an omitted build as optional `NOT_RUN` with its reason. List `blocks_visible`, `blocks_functional` and `package_size` as not executed. Store actual evidence under the run's `evidence/`; one report with distinct check sections may support multiple check IDs using the same file and SHA-256.

Finish with a terminal `REPORTED_FINDINGS` handoff, then run `mpa.py transition`. Record each static gate as its actual evidenced `PASS` or `FAIL` (a failed gate is P0); record `builder_build` as `PASS`, `FAIL`, or optional `NOT_RUN`; record the two observation checks and `package_size` as optional `NOT_RUN`. This handoff is valid only for a review-only route with no publication successor. It has no `basic_review` artifact and no `REVIEWED_BASIC` outcome; the `PASS` status means the findings report was delivered, not that the project passed Basic. The terminal transition retains the run evidence automatically.

Passed static evidence is reusable in a later full Basic while the project hash remains current. A failed gate must be fixed and rechecked; later Basic still adds the build, the two observation checks and the package size. Decide the branch up front from the request, before starting evidence work.
