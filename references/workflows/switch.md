# Leaf: fresh V1-to-V2 conversion

Load this leaf only for `CONVERT_FRESH`.

Before source-dependent writes, complete [Lite source selection](../official-repository-discovery.md). Preserve its comparison/fork evidence and add required `lite_source_selection` to the producer handoff.

Before npm lifecycle scripts or extension loading, inspect install hooks, dependencies and executable code for unexplained dangerous behavior per the security scope in [Basic](../review-basic.md). Reuse this evidence in the later Basic review; do not execute suspicious code merely to test it.

## Embedded component boundary

The complete conversion workflow is packaged inside `mindplus-extension-skills`: executable helpers live in `scripts/switch/`, curated guidance and the verified reference bundle live in `references/switch/`. Never resolve a sibling checkout, a separately installed `mindplus-switch` Skill, or a caller-supplied switch root. The name `mindplus-switch` in existing logs and handoffs is only the internal producer identifier.

Convert exactly one V1 library and one registered mode per run. Keep the V1 source read-only. Prepare the latest stable Git-free Builder Release directly as the final project root, convert into its root `extension/`, update the root `README.md`, and attempt one Builder build when the package stage passes. Build success is not independent review, Mind+ import, runtime, upload, or device acceptance.

## Inputs and boundaries

Require absolute `v1_source` and `work_root`. Accept optional `project_root`, `mode: UPLOAD | PYTHON_BLOCK`, and `review_policy: AUTO | SENSITIVE_REVIEW`. Never modify the V1 source, a shared Builder checkout, the private Wiki, or unrelated files. Do not commit, push, publish a release, package, import, upload, flash, install target Python/Arduino dependencies, or run a second install/build attempt. A host package-stage stall is a handoff, not a conversion failure and not permission to retry.

Load references at the steps below, once per run. Select one supported mode before reading its mode guide; do not preload both branches or the full generated corpus.

## Workflow

1. **Open the checkpoint.** Read [run-log.md](../switch/run-log.md) before creating or resuming the child record. Run `scripts/switch/init_run.py --parent-run-id <parent_run_id>` using the parent wizard command before conversion work. Create `<parent_run_root>/children/CONVERT_FRESH/log.md`; `.mindplus-agent` stores records only (hidden on Windows, and removable via `mpa.py clean --all` once the run is finished) and is not the final project or a security boundary. After every step call `scripts/switch/update_run_log.py`; a stale `RUNNING/S-1` log is not a completed run. Stop if logging fails or the run would modify the V1 source.

   Use the child `run_root` returned by init_run for every `record/` path below; the parent run root remains the handoff/transition location. Repeated initialization of matching inputs reuses the same child without resetting its checkpoints. See [run-records.md](../run-records.md) for analysis and legacy records.

2. **Check the reference release.** Read [reference-release.md](../switch/reference-release.md) for bundle selection and fallback. Run `scripts/switch/check_reference_release.py --skill-root <skill_root> --output <run_root>/record/reference-state.json`. This checks only the configured release manifest and verified local data; it never crawls the Wiki. Record status, release ID, content hash, supported modes, and `active_root`. A valid bundled/cache fallback may continue with a warning; no valid bundle is `BLOCKED/REFERENCE_BUNDLE`.

3. **Route from V1 facts.** Apply [routing-policy.md](../switch/routing-policy.md). Run `scripts/switch/inventory_v1.py --source <v1_source> --output <run_root>/record/v1-inventory.initial.json`. `arduinoC/main.ts` is `UPLOAD`; `python/main.ts` is `PYTHON_BLOCK`. Use its candidates for routing and its `reference_features_by_mode` only after selecting one mode. Record `candidates`, `selected`, `source_anomalies`, evidence, and confidence before loading mode details. One supported candidate continues. Both candidates, a tie, a conflict with an explicit mode, or an unknown/planned mode stops at the routing state defined in `routing-policy.md`; never guess.

4. **Select and load only required facts.** Read [shared-v2-patterns.md](../switch/shared-v2-patterns.md) and [conventions.md](../switch/conventions.md), then only the selected mode guide: [UPLOAD](../switch/upload-mode.md) or [PYTHON_BLOCK](../switch/python-block-mode.md). Run `scripts/switch/select_reference_topics.py --inventory <initial_inventory> --reference-state <reference_state> --mode <selected_mode> --output <run_root>/record/reference-selection.json`. Require `PASS`; otherwise stop as `BLOCKED/REFERENCE_SELECTION`. Read only the returned Topic paths, in order, plus the curated mode and shared-pattern references already selected above. Record the selection file and Topic IDs in `log.md`, including `reference_selection`. Generated Wiki facts define current V2 fields and APIs; curated references define migration decisions. A generated/curated/V1 conflict is a sensitive node and must not be guessed through.

5. **Prepare the final project.** Read [builder-workspace.md](../switch/builder-workspace.md). Choose an explicit `project_root` satisfying [project-naming.md](../project-naming.md), or derive `<work_root>/ext2-<ul-or-py>-<safe-v1-id>` only when the V1 ID is already unambiguous and safe. It must be outside the V1 and `.mindplus-agent`, and absent or empty. Run `scripts/switch/prepare_builder_scaffold.py --project-root <project_root> --output <run_root>/record/builder-scaffold.json`; it downloads and verifies the latest stable `mindplus-ext2-builder-Scaffold.zip`, accepts root-level files or strips a single wrapper directory, and rejects `.git`, `examples`, build products, unsafe paths, or a mismatching published SHA-256 when supplied. Do not use the tag source archive or `git clone`. If the anonymous release channel answers `403`/`429`, follow the rate-limit recovery in [builder-workspace.md](../switch/builder-workspace.md) (authenticated read-only release lookup, then `--archive`/`--sha256`); record release URL/tag/hash and prove the target is exactly `project_root/extension`. Do not run `git init`, add a remote, commit, or push unless the user separately requests that Git action.

6. **Install once, with a bounded wait.** In `project_root`, record Node/npm versions and set `install_attempt: 1` immediately before starting exactly one `npm install`. Follow the stall protocol in [references/builder-workspace.md](../switch/builder-workspace.md). If the command has no observable progress for the configured window, exceeds the wall-clock window, or the host reports a lock, socket, permission, or Node-manager problem, stop waiting once: set `install_status: USER_ACTION_REQUIRED`, mark S4 `BLOCKED`, and continue the source conversion and static steps S5–S9 without starting a build. Do not use `npm ci`, repair the environment, or retry. A non-zero exit without a stall is `install_status: FAIL` and stops as `BLOCKED/BUILD_ENV`.

7. **Freeze and convert behavior.** Apply [config-schema.md](../switch/config-schema.md) when generating config. Run `scripts/switch/inventory_v1.py` again as `record/v1-inventory.pre-conversion.json`, then run `scripts/switch/compare_inventory.py` and save `record/v1-snapshot-check.json`; source drift stops the run. Use inventory `canonical_v2_id` for the new lowercase alphanumeric V2 ID and `expected_compatibility_id` for the unchanged legacy package identity; never derive compatibility from the cleaned ID. Run `scripts/switch/create_config_skeleton.py --source <v1_source> --inventory <pre_conversion_inventory> --mode <selected_mode> --output <project_root>/extension/public/config.json` on the fresh scaffold, then edit only values backed by evidence. Build a semantic matrix for every visible block, menu, parameter/default, generated-code fragment, dependency, resource, and board condition. The skeleton/profile defines the only allowed config fields, includes every required field, keeps mode/fixed values exact, and writes `""` for an undocumented string value. Do not copy V1 `email`, `license`, `isBoard`, `platform`, or `asset`; do not invent `boardConfig`. In `PYTHON_BLOCK`, use only the inventory's `config.json:asset.python.dependencies` and exact `python/libraries/requirements.txt` records for dependencies; do not infer, omit, upgrade, or resolve them from imports or README. Preserve V1 opcode/function names, parameter keys/order, menu values, block types, assets, libraries, and generated behavior unless a documented sensitive decision authorizes a change. Convert every user-visible extension, block, and menu label through stable `formatMessage` IDs and both target locale files. Write implementation only to `project_root/extension`; the root README is the sole additional project file authorized by step 8. Verify verbatim copies with `scripts/switch/verify_source_copy.py`, then set `copy_check: PASS` or the actual terminal result. The verifier reads real files from two roots, so a V1 Arduino library packed as `arduinoC/libraries/libraries.zip` cannot be hashed in place: extract that archive into a temporary directory outside `project_root` and outside the V1 source, build the mapping `extracted/<relative path>` → `public/libraries/<relative path>` (plus one entry per reused image or icon), and pass those as `--source-root`/`--target-root`. The resulting evidence JSON embeds both digests and sizes for every entry, so it stays self-contained and the temporary extraction may be deleted afterwards.

8. **Update the root README.** Read [references/project-readme.md](../switch/project-readme.md), replace the Builder template with evidence-backed project content, and run `scripts/switch/check_project_readme.py`. Record `readme_check: PASS` or its terminal result. Missing facts, placeholders, or broken local links stop before build.

9. **Scan before build.** Run `scripts/switch/check_converted_extension.py --project-root <project_root> --inventory <pre_conversion_inventory> --mode <selected_mode> --output <run_root>/record/conversion-check.json`; add `--expected-v2-id <approved-id>` only when the user explicitly chose a non-default legal V2 ID. Classify each finding by actual impact using [issue-levels.md](../issue-levels.md). P0 defects and unmet independent identity/source gates stop before build; color and other P1/P2 presentation findings remain advisory — for `PYTHON_BLOCK`, assess dependency declarations under [Basic](../review-basic.md): standard and target-bundled libraries need no additional declaration; missing declarations for third-party packages requiring installation are P1. Preserve the original V1 dependency declarations during conversion. Preserve the raw checker output and evidence; an aggregate FAIL containing only advisory findings does not itself block the build. Confirm config/index/func parsing, copy verification, README check, and zero prior build attempts.

10. **Build once, with the same bounded wait.** Only after `install_status: PASS`, set `build_attempt: 1` immediately before one top-level `npm run build`. If `install_status` is not `PASS`, do not start it: set `build_status: SKIPPED_DEPENDENCY`, keep `build_attempt: 0`, mark S10 `BLOCKED`, and proceed to handoff. If build stalls under the same protocol, set `build_status: USER_ACTION_REQUIRED`, mark S10 `BLOCKED`, do not retry, and hand `npm run build` to the user. A non-zero exit without a stall is `build_status: FAIL`; do not repair and rerun. Pass requires exit code 0, a fresh target `main.js`, and expected `public/` assets.

11. **Finalize and hand off.** Update the structured summary fields as well as the append-only event. Run `scripts/switch/check_run_log.py --log <run_root>/log.md`; fix missing or contradictory log fields before reporting. Mark S11 `PASS` only for a verified terminal result, or `BLOCKED` for an explicit user handoff. Set `review_status: NOT_RUN`. Report `CONVERTED_BUILD_PASS`, `CONVERTED_BUILD_FAIL`, or `CONVERTED_HANDOFF` accurately; a skipped or stalled install/build can never be reported as a build pass.

## Completion output

Return absolute paths for `run_root/log.md`, `project_root`, `project_root/extension`, build output when it exists, and `conversion-check.json`. The log must no longer be `RUNNING`; it must contain route evidence, identity mapping, reference release/status/root/selection, Builder revision, install/build attempts and statuses, changed files, copy/README/conversion checks, first failure cause, user action, and next workflow. If stopped, return the reason code and exact missing input or decision. `CONVERTED_HANDOFF` means the conversion/static gate is complete but the user must run the recorded package command outside this run.


## Parent handoff

Keep the detailed child conversion log as evidence, then create and validate a parent-compatible handoff:

| Internal result | Parent state/status | Parent outcome |
| --- | --- | --- |
| `CONVERTED_BUILD_PASS` | `TERMINAL/PASS` | `CONVERTED` |
| `CONVERTED_BUILD_FAIL` or a blocking conversion result | `TERMINAL/FAIL` or `TERMINAL/BLOCKED` according to evidence | `CONVERSION_NOT_READY` |
| `HANDED_OFF` or `CONVERTED_HANDOFF` with passing static checks and an unavailable optional build | `TERMINAL/PASS` with build optional/NOT_RUN | `CONVERTED` |

Set `review_status` to `NOT_RUN` until the next Basic leaf completes. Producer/static completion proceeds to REVIEW_EXISTING; unavailable build or block observations remain explicit and block publication, even when source conversion itself is complete. Basic reuses the current build instead of repeating it.

Before parent handoff, apply [issue-levels.md](../issue-levels.md). P0 blocks; P1/P2 remain evidenced advisory findings. Preserve raw checker results and separate presentation findings from required functional gates.
